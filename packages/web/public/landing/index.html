§ the problem

Every AI builder reaches for the same fonts, gradients, and hero.

v0, Lovable, Bolt and Cursor were trained on the same web, so their output converges. Ship a few generated sections and your page starts to read like everyone else’s — and you can’t see it, because you’ve been staring at it. slop‑detect is the outside eye: it tells you which specific defaults crept in, and exactly how much weight each one carries.

§ how it works

Real Chromium. Pure functions. One number.

There is no model and no randomness anywhere in the path. The same page always produces the same score, so you can put it in CI and trust the diff.

load →

Open the page

Headless Chromium loads the URL exactly as a browser would: JavaScript, fonts, computed styles and all.

inspect →

Read the styles

Up to 4,000 visible DOM nodes are checked against the catalogue. Each detector is a pure function over the live computed styles.

weight →

Add the tells

Every triggered pattern adds its fixed weight. Slop is the density of converged tells, not any single one.

grade

Clean / Mild / Heavy

The 0–100 total maps to a tier and a letter grade. Clean 0–9, Mild 10–27, Heavy 28+.

§ what it checks

Four axes, one report.

The design fingerprint is the headline, but a page can look hand‑made and still fail elsewhere: read like an LLM, be invisible to AI search, or quietly drift off its own brand. Each axis is named, weighted, and contestable. It is a fingerprint, not a verdict on the people who built it.

  • design 27 CSS & layout tells

    Slop fonts, gradient hero text, glassmorphism, aurora blobs, the eyebrow pill, the centered hero. Lower is better.

  • copy AI phrasing

    The hedge‑y, em‑dash‑heavy register LLMs default to, scored on the words themselves. Optional second axis.

  • aeo AI readability

    Can ChatGPT, Claude and Perplexity actually fetch, read and cite the page? Higher is better.

  • system DESIGN.md compliance

    Does the page honor its own declared design system? Checked against your tokens, so bespoke work can’t be mistaken for slop. Higher is better.

§ run it

Wherever the page gets built.

terminal

Scan one URL or many. No install ceremony.

$ npx slop-detect https://your-site.com

CI gate

Fail a pull request when a redesign drifts into Heavy.

$ slop-detect $URL --fail-on heavy
# exit 1 if the page scores Heavy

coding agent (MCP)

HTTP API

One POST, JSON back. No key for normal use. OpenAPI published.

$ curl -X POST .../api/scan \
  -d '{"url":"https://..."}'
§ the honest part
“Everyone uses AI now. Won’t this just flag good sites that use Inter?”

It scores density, not provenance. One default isn’t slop; premium sites that use Inter land in Mild, not Heavy. And the system axis checks a page against its own DESIGN.md, so a deliberate, bespoke design is measured against its own rules instead of a global average. The score is a signal to read, never a verdict on the team. Every tell links to a named, contestable rule.

§ keep it clean

A score is a snapshot. Drift is the disease.

Sites don’t turn generic in one commit — a teammate ships a section, an agent “improves” a hero, and six weeks later the page has drifted. Monitor a domain and slop‑detect re‑scans it daily, emailing you when the score regresses or the page drifts off its DESIGN.md (double opt‑in; nothing is sent until you confirm). The engine stays free forever; monitoring is the optional layer on top.
